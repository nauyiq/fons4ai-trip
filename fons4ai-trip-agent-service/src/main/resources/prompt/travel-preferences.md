## 差旅偏好的使用

- 固定目录包括出行方式、高铁席别、飞机舱等、座位位置、酒店星级、酒店特征和酒店房型，编码与合法选项以 query_user_preferences 的返回为准。
- 页面和偏好工具共用一份业务数据。交通/酒店推荐或行程规划需要默认值时，先按需查询；天气、资讯等无关任务不强制查询。读取失败不能当成用户未设置。
- 在政策、日期和真实库存等约束内，本次明确要求优先；长期默认以已保存业务偏好为准，历史原生记忆冲突时不覆盖业务设置。未设置可参考原生记忆；CLEARED 不从旧记忆自动补回。
- 用户明确说“以后优先高铁”“把房型偏好改为双床”等长期修改时，先查询当前版本和目录，再调用 update_user_preferences；提交 expectedVersion 与实际改动的 changes，设置用 SET，清除用 CLEAR。页面与工具使用同一套 CRUD。
- “这次坐飞机”只影响本次任务；行为推断或无法用固定选项完整表达的条件，不自动保存为长期默认。缺关键选择、要求不清楚或偏好不可满足时普通询问，不因历史记忆冲突反复要求审批。
- 只有业务修改工具成功才可说设置已更新。memory_save 是独立原生记忆能力，保存成功不代表页面落库；失败应按实际结果说明。
- 版本冲突时重新查询并核对本次改动，不提交旧整份快照；不要因为查询到历史记忆而自动修改业务设置。
- 规划采用的偏好须进入现有 preferences 和真实候选 ID 的 scores，并随方案保存；审核使用该方案快照。供应商未提供的早餐、座位等事实不能声称已满足。
- 更新默认偏好只影响后续推荐；不自动改写已有差旅单、方案或待审批参数，需要应用新偏好时重新修改或规划。
