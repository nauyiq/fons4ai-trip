## 任务

- [ ] **T-1：形成框架分段执行摘要**
  - 依据：AC-3/4/6/7；[设计契约与执行边界](技术设计.md#contracts)。
  - 范围与边界：公共 AgentRunResult/AgentRun、既有 AgentScopeRunContext、生命周期中间件和 ToolExecutor 兼容补丁。保持一个 HarnessAgent；不改变父子正文/状态/HITL 隔离，不新增根采集器。
  - 实施要点：固化 ModelCall/ToolCall 的身份、空值和完成口径；每次本地模型调用记录一次最终 usage；实际工具入口区分执行与 Guard 短路；只读摘要入口覆盖取消迟到结果。核对未支持统计的适配器如何表达未知，不把占位项当真实调用。无效负 usage 不进入总量。
  - 验证与完成：生产构建成套安装 common/starter；重启后核对实际补丁加载来源。对一条父子只读调用，检查一次模型/工具只产生一项相应执行；审批等待、拒绝和短路不误算，取消后迟到结果可在最终摘要解释。构建和行为证据俱全后完成。
  - 依赖与解除条件：R2 对公共查询入口和 SDK 补丁边界获得确认；框架产物被 Trip 实际加载。

- [ ] **T-2：让分析步骤返回本次结果及用量**
  - 依据：AC-1/4；[分析与 Pipeline 结果](技术设计.md#contracts)。
  - 范围与边界：QueryRewriteAgent、IntentRecognitionAgent、ExtractUtils、分析 Handler、既有 PipelineResult/上下文。不强制接入框架 Harness，不改变规则/缓存/意图业务判断。
  - 实施要点：现有模型处理处取最后非空 usage，Handler 在解析业务文本之前保留本次用量；没有响应保留未知；缓存/规则/恢复跳过不生成调用。正常 PipelineResult 返回汇总，异常收尾保留同一上下文已知结果。
  - 验证与完成：普通请求经过两次分析后，结果和用量均可追到对应 Run；规则/缓存/恢复跳过的分支无虚假模型消耗。若解析失败，已经获得的模型 usage 仍能在退出后的请求摘要中定位。逐项记录真实前提与结果后完成。
  - 依赖与解除条件：T-1 的摘要结构稳定；不以 Mock 或单元测试替代真实用量核对。

- [ ] **T-3：完成两表投影与退出收尾保存**
  - 依据：AC-1/2/3/4/5/6；[保存时序](技术设计.md#flows)、[数据映射](技术设计.md#storage)。
  - 范围与边界：ChatMessageAggregate、ChatRequestTrace/领域服务、ConversationApplicationService、业务 Guard、schema 与迁移。保留取消提示持久化和 PREPARED→PENDING 原子交接。
  - 实施要点：业务工具按 Trip 注册清单分类；JSON 保存调用明细和完整性；显式更新 NULL 用量而不覆盖权威状态。正常结果事务保存正文/票证/Trace；真实退出事务补齐摘要并清占用/开放审批。来源只从白名单业务结果提取，不覆盖完整原响应。Master 思考选一个消息载体，防止多卡复制。
  - 验证与完成：MCP 确认迁移列（已完成此项）；用户重启后执行普通完成、双审批恢复、模型中取消和工具中取消。按 runId 读取两表，核对旧新分段、工具、用量与取消提示；确认 active_run_id 清理及票证状态一致。取消/失败缺少 usage 时显示不完整。数据库失败回滚路径若无可用安全故障注入环境，明确保留未验证项，不假称通过。
  - 依赖与解除条件：T-1/2 就绪、人工迁移生效（已解除）、R2 业务分类等差异已处理；重启后才可验收新实例。

- [ ] **T-4：完成两来源历史读取与最小展示**
  - 依据：AC-1/2/3/8；[历史 API 与交互](技术设计.md#interaction)。
  - 范围与边界：原消息分页接口、MessageInfo/RequestTraceInfo、chat API、ChatWindow、摘要组件及思考展示；不开发任务看板，不改变审批提交协议。
  - 实施要点：鉴权后按页批量关联 Trace，使用 runId 归组、messageId 合并。明确摘要在首次出现的 Run 消息处展示，正常正文/多媒体/多卡不重复。补齐审批分支的一份 Master 思考展示和真实来源。存量缺失/坏 JSON 安全退化为未知，不能使整页失败或被误解为零。
  - 验证与完成：TypeScript/Vite 构建通过；普通请求与双审批刷新后各仅一份分析摘要和实际思考；旧会话可读，跨页同 Run 不重复，另一用户越权读取仍拒绝。截图、接口响应和 MCP 记录能相互关联后完成。
  - 依赖与解除条件：T-3 数据契约固定；R2 审批思考载体及容错目标获得确认并实现。

- [ ] **T-5：最小真实验收与知识沉淀**
  - 依据：全部 AC；[设计验证表](技术设计.md#verification)。
  - 范围与边界：用户测试环境中的只读业务查询、审批与取消；相关 Wiki 增量维护。不启动后端，不自动执行数据库修改，不新增/运行单元测试，不下单/预订/支付。
  - 实施要点：先复核本次实际加载产物，再按设计验证表执行最少能覆盖分支的请求；比较每项 usage 与总量、内部工具与业务工具、来源可信性、恢复新 Run 和取消迟到结果。单独核对关闭观测后业务摘要不受影响。只将有证据的事实更新进原 Wiki，未验收项留在本任务文件。
  - 验证与完成：每项 AC 有可定位的 Run/接口或数据库证据；不完整用量有明确显示；构建、迁移、部署和业务验收分别记录。未覆盖 AC 不勾选，不以文档完整或编译成功宣布功能完成。
  - 依赖与解除条件：T-1 至 T-4 收敛、用户确认 R2 实施基线、用户重启加载新产物；关闭观测场景需要用户切换配置并再次重启。
