# Trip 工程约定

[项目地图](index.md) · [协作指引](../../AGENTS.md)

这里整理已有实现与用户明确决定中对后续工作有约束的部分，不将所有历史代码写法都视为标准。业务规则由各业务专题维护，以下约定不授权存量代码全量迁移。

## 模块与职责

| 场景 | 沿用的入口与边界 | 代表性依据 |
| --- | --- | --- |
| HTTP 与可信用户 | Controller 从登录态取身份，验证请求并委托应用服务；不信任模型或客户端声明的归属 | [ConversationController](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/controller/ConversationController.java) |
| 多资源业务流程 | 应用服务组织事务与动作顺序，领域服务操作业务实体，基础设施处理外部协议/存储 | [TravelBusinessApplicationService](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/application/business/TravelBusinessApplicationService.java) |
| 工具接入 | 业务工具负责参数与可信上下文适配，委托应用服务；供应商协议留给 Client | [ItinerarySearchTools](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/agent/tool/ItinerarySearchTools.java)、[搜索应用服务](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/application/itinerary/ItinerarySearchApplicationService.java) |
| 框架通用能力 | 先查现有 API、装配和实际版本，复用扩展点；不按类名猜测方法或重复包装未知能力 | [框架接入专题](framework-integration.md) |

这些是当前代表性路径。局部功能应先定位相应封装，不能只根据目录名称推断某项行为已经具备事务、权限或重试保证。

## 身份、结果与权限

- 用户身份来自服务端登录态；候选、规划、审核、页面使用可信用户与根业务会话。不要退回 SDK 子会话 ID，也不要以 Trace 是否开启决定业务归属。依据：[TripRuntimeContext](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/infrastructure/agent/TripRuntimeContext.java)。
- 普通业务返回沿用 `R`、既有结果码及业务/系统异常；工具的业务失败、外部调用异常和空结果分别处理，不把它们统一改成“查询成功但无数据”。
- `run_ended` 是应用对外的分段收口通知；过程事件、任务清单完成、HTTP 断开与模型文本不能替代权威结果。详见 [会话执行](conversation.md)。
- 工具许可、差旅单审批和方案审核分别建模；提示词中的“确认后执行”与 SDK ASK 规则不是同一种强制约束。
- 密钥不进入 Wiki、模型提示词、候选快照或完整错误回显。需要说明配置时写属性名、用途与来源，不复制运行配置值。

## 事务与并发

复合业务修改沿用应用服务已有的 `TransactionTemplate` 事务组织，检查保存结果；不要仅凭 `@Service` 认定跨调用原子执行。审批恢复使用条件更新及可信持有者字段，重要异常不能被吞掉后宣布成功。依据：[ConversationApplicationService](../../fons4ai-trip-agent-service/src/main/java/com/fons/cloud/ai/trip/application/conversation/ConversationApplicationService.java)。

同一会话的执行占用分别由 Redis 租约和数据库条件更新保护；释放要匹配当前 Run，实际退出前不交还执行权。业务写入的旧执行隔离与完整故障接管不是当前租约方案的已有保证。

用户明确要求：需要锁协调复合状态时优先 JUC 原子类或 Lock，不新增以方法入参为监视器的 `synchronized`。线程安全容器不自动保证跨字段、跨存储的操作原子性；需要时参考框架已实现的生命周期边界。

## 可读性与演进

为字段、对外方法和关键业务边界补必要注释，解释可信来源、状态限制、事务交接与例外，而不逐行复述代码。命名、异常和日志优先沿用目标模块约定，不为小改动增加新的委托层、调度器或基础设施。

模型输出用于提出参数和方案；客观金额、归属、候选引用、审核与发布资格由可信数据和服务判断。具体约束见 [行程规划](itinerary-planning.md)，避免把提示词要求误写成代码保证。

## 验证与知识维护

当前协作不新增或运行单元测试，后端由用户启动；MySQL 仅通过 MCP 只读验证，DDL/DML 由用户执行。这些来自当前用户约定，不据此删除既有测试或推导外部团队流程。命令统一见 [README](../../README.md#运行与开发)。
